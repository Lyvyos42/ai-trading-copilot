# Signal engine audit — 2026-09-05

Triggered by a production screenshot: 50 signals, every one BEARISH, all
timestamped 15h ago, WINS 0 / LOSSES 4, every row showing R:R 3.5:1.

## The finding

**Six of the nine agents produce their entire output from a seeded random
number generator.** Not as a fallback that rarely fires — as the live
production path.

Proof, not inference. The bull case rendered on screen reads:

> EURJPY=X shows positive earnings momentum (EPS growth: 6.0%). Value score is
> stretched at P/E 28.2x. Applying strategy 3.2 (earnings momentum) and 3.3 ...

That is a character-for-character match to the f-string in
`backend/app/agents/fundamental.py::_mock_analysis`, whose inputs are:

    eps_growth = market_data.get("eps_growth", rng.uniform(-10, 30))
    pe         = market_data.get("pe_ratio",   rng.uniform(10, 35))

EURJPY is a currency pair. It has no EPS and no P/E, so both defaults fire
every time. The "6.0%" and the "28.2x" are random numbers.

`_call_claude` returns None when there is no API key, and every one of these
agents then falls through to its mock. `python_engine_mode = True` is
documented in GEMINI.md as "all 9 agents execute pure mathematical and
statistical calculations directly in Python". What executes is
`random.Random(sum(ord(c) for c in ticker) + date.today().toordinal())`.

The seed is derived from the ticker and the date, so output is *stable within
a day*. That is why this looked like analysis for so long: it does not flicker.
It is a hash of the symbol's name wearing the costume of research.

## Agent by agent

| agent | status | what is fabricated |
|---|---|---|
| technical | **REAL** | EMA/RSI/ATR computed from actual OHLCV |
| order_flow | PARTIAL | real `vwap_dev`, `vol_ratio`, `obv_trend`, then `+ rng.uniform` noise injected into VPIN and bid/ask imbalance |
| sentiment | **FABRICATED** | headlines drawn from a hardcoded `MOCK_HEADLINES` list, then "analysed" |
| fundamental | **FABRICATED** | EPS growth, P/E, value score, revenue growth |
| macro | **FABRICATED** | regime, Fed stance, inflation, GDP, geopolitical risk index, FX carry |
| regime_change | **FABRICATED** | stability, change probability, VIX term structure |
| correlation | **FABRICATED** | base correlation, contagion, diversification |
| risk_manager | **FABRICATED** | drawdown, sector concentration, correlation, vol scalar |
| quant | **FABRICATED** | win rate, sample size, p-value, Sharpe, expectancy |

## The two that must be fixed before anything ships

**quant.py** manufactures a track record and then reasons about it:

    base_wr   = 0.45 + agreement * 0.15 + rng.uniform(-0.05, 0.05)
    n_samples = rng.randint(80, 350)
    z         = abs(win_rate - 0.5) / sqrt(0.25 / n_samples)
    statistical_edge = p_value < 0.05 and win_rate > 0.52

A win rate and a sample size are invented, a p-value is computed from them,
and the result is presented as a significance verdict — including notes like
"p-value 0.03 < 0.05: edge is significant". No data was involved at any point.

**macro.py** labels its fabricated output as live:

    f"Live macro analysis: regime is {regime}. "
    f"Geopolitical risk index: {geo_risk:.0f}/100. "

with `geo_risk = regime_data["geo_risk"] + rng.uniform(-10, 10)`.

This matters commercially and not only technically. Serving a signal and
letting the customer decide is a sound model — it is defensible precisely
because the signal is the system's honest best estimate. It stops being
defensible when the page also shows a win rate, a p-value and a P/E that were
generated by `rng.uniform`, with the word "Live" on them.

## Secondary defects from the same screenshot

- **R:R is a constant, not a measurement.** `_PROFILE_PARAMS["balanced"]` is
  `target_atr 3.5 / stop_atr 1.0`, so every signal is 3.5:1 by construction.
  It is an assumption printed as a finding. At 3.5:1 the breakeven win rate is
  ~22%; the panel reports 0%.
- **Nothing resolves signals.** `signal_resolver.py` exists (264 lines) but no
  scheduler calls it — `main.py` never references it. So 46 of 50 signals sit
  unresolved forever and WINS/LOSSES counts only hand-pressed buttons. The
  0% win rate on the page is not a measured 0%; it is 4 manual clicks.
- **Asset class is wrong.** EURJPY=X is tagged `stocks`, which is what routes
  it to the equity fundamental agent in the first place.
- **Percentage signs are inverted.** Research target $174.185 against a price
  of $181.482 is -4.0%, displayed as +4.0%. Invalidation $183.320 is +1.0%,
  displayed as -1.0%.
- **Direction is uniformly SHORT** across 50 signals and 6 symbols. Not yet
  diagnosed; needs the fabricated inputs removed before it can be.

## What follows

A restructure cannot raise the win rate of a system whose inputs are random —
there is no edge to find in `rng.uniform`, so no amount of architecture will
produce one. The order has to be:

1. Delete every fabricated path. An agent with no real data source returns
   `NEUTRAL` with `confidence: 0` and says so, rather than inventing a number.
2. Wire the agents that *can* be real to real data.
3. Schedule the resolver so outcomes are measured rather than clicked.
4. Only then measure, and only ship what measures well — the same harness
   discipline used in IEB: honest cost, out-of-sample, multiple-testing bar.

Step 1 will make the app look *worse* — most agents will report NEUTRAL and
few signals will pass. That is the point. The current 66% conviction figure is
noise with a decimal point.
